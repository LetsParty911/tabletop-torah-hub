- Maintenance mode state lives only in Lovable Cloud table public.site_maintenance (row id=1), toggled from the admin Maintenance control; read server-side and fails closed. Why: a source flag could silently flip on unrelated publishes.
- City-block check skips lookups when the edge country has no blocked city, memoizes per-IP results in the isolate, and time-boxes lookups (fail open). Why: blocking must never add an external request to every page view.
- Keep the /admin since-last empty-state decision in the pure admin mini-summary helper. Why: Open PDF clicks and legacy downloads must both prevent a false empty report.
- Maintenance-screen hits are logged server-side (request middleware after geoBlock) into Lovable Cloud public.maintenance_visits with no raw IP/UA/query strings, never into canonical analytics. Why: the maintenance view never mounts client analytics, and its traffic must not inflate visitor/PDF totals.
- VPN alerts: the analytics DB trigger queues `vpn_blocked` rows in vpn_security_notifications; the Worker (src/lib/vpn-notify.server.ts) claims queued rows (queued→sending) and sends Pushover, and only inserts its own rows for provider failures or when the audit write failed. Why: one queue, no duplicate alerts, no service-role key in DB webhooks.
- The VPN 403 decision is made before any logging; failed audit writes fall back to Lovable Cloud public.vpn_audit_failures. Why: blocking must never depend on the analytics database.
- Generic owner alerts live in src/lib/notifications/ (pure core + dispatch.server) with a durable outbox in the analytics DB (docs/notifications/); they never touch VPN alerts or the first-load visitor alert. Why: independent, idempotent delivery that can't regress working alerts.
- Keep PDF event/qualification display translations in the pure pdf-reporting helper; retain raw event names and qualification values. Why: truthful report wording must not change tracking or historical metrics.
- Reuse WeeklyEmailSignup for additional signup placements with distinct anchorId and sourceId props, leaving its default anchor on the lower homepage form. Why: consent, feedback, attribution, and existing scrolling remain consistent without duplicate DOM IDs.
- Reserve external settings.updated_at for explicit parsha override saves; unrelated settings writers must omit it. Why: shared timestamp renewal otherwise reactivates archived overrides without consent.
- Keep weekly deadline and override validation in pure helpers; availability requires current-year published rows, and completion requires week-bound progress evidence. Why: last-week fallback PDFs and legacy progress cannot prove a current release.
- Run weekly handler mocks with vitest.weekly.config.ts, separate from the framework Vite config. Why: RPC transformation replaces the handlers that isolated tests must actually exercise.
